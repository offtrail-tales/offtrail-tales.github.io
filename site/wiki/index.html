Offtrail Tales

Offtrail Tales plays interactive stories with pictures, music, sound and video. Stories are written in ink, inkle's language for interactive fiction. Each tale fits in one .tale file: import it and play it in a browser, on a computer or a phone.

The app

Title screen

The first screen shows the app's background art and logo. "Press any key" starts on a keyboard; "Tap to start" on a touch device. The menu music begins after the press.

Main menu

A list of tale cards, built-in tales first, then imported tales. Below the list:

  • Import tale opens a file picker for a .tale file.
  • Write a tale links to the tale editor.
  • Settings opens the Settings sheet.
  • About describes the app and its safety.
  • Credits lists licences, art and music credits.

Tale cards

Each card shows the tale's cover picture (or a default tile), title, authors, description, language, size and version. Imported tales are marked "Imported".

Press a card to see its actions:

  • New game starts the tale from the beginning. It warns when it would replace a game in progress.
  • Continue resumes from the autosave (shown only when one exists).
  • Load game opens a file picker for a saved game (.otsave).
  • Remove tale (imported tales only) deletes the tale and its autosave from the browser, after a confirmation.

Import a tale

"Import tale" opens a file picker for a .tale file. The app checks every file in the tale against its hashes, with a progress bar. It warns when a tale with the same ID is already imported (replace or cancel) and when the browser does not have enough storage space.

A .tale file holds data, not code. It is safe to accept from anyone.

New game and the title card

A new game opens on the title card: the tale's title, authors and cover picture, over the theme's background. Any key or tap starts the first passage.

The game screen

The top bar has a menu button (hamburger), the tale's title, and a Map button when a map tag is active.

Below is the story: text and pictures scroll in a column. After each passage, the player picks a choice at the bottom. The chosen option stays in the story as a divider.

If the story crashes at runtime, the player sees the error and returns to the main menu.

Speech

A line written as Name: line shows the speaker's name once, above a run of their lines. The name is up to three words, each starting with a letter. Narration with a colon stays narration (for example, "He had one rule: never look back.").

The End

When the story ends, the screen shows "The End" with two buttons: Main menu and Play again. The autosave is deleted.

Game menu

The menu button in the top bar opens:

  • Resume closes the menu.
  • Save game downloads an encrypted .otsave file.
  • Load game opens a file picker for a .otsave file.
  • Settings opens the Settings sheet.
  • Main menu returns to the tale list.

Save files

The app saves automatically after every choice. Each tale has one autosave, encrypted in browser storage. "Continue" on a tale card resumes it.

"Save game" downloads an .otsave file. "Load game" opens one. A save from a different version of the tale warns before loading. A save from a different tale asks to switch.

Maps

When a map tag is active, a Map button appears in the top bar. It opens the map picture. The player can zoom (scroll wheel, pinch, keyboard plus and minus, or buttons) and drag to pan.

Settings

  • Theme: Classic, Neon City, or Scandinavian 80s. Each has its own background art and colour palette. While a tale with its own theme plays, a note says the tale's colours will come back.
  • Text size: Small, Medium, or Large.
  • Master volume: a slider that also shows in the sound rail.
  • Music volume: relative to the master.
  • Sound effects volume: relative to the master.
  • Test buttons: play a short preview of Music, SFX, Music + SFX, or Video.
  • Clear saved data: deletes all autosaves, imported tales and settings from the browser, after two confirmations. The page reloads.

Sound rail

On every screen: a mute toggle and a volume slider at the right edge. Moving the slider unmutes. Unmuting at zero volume brings it to 50%.

Sound and video pause when you switch to another app or tab, and carry on when you come back.

About and Credits

About explains what the app is, its safety statement ("no account, no tracking, nothing leaves your device"), and a "What's next" note.

Credits lists the licences of the engine, its libraries, art, music and the sample tale. Both end with the build version.

Tale themes

A tale can bring its own six colours and a background picture. The app wears them from the title card through the game screen, the game menu, Settings and videos. The main menu keeps the player's own theme.

Media tags

Tags link story text to media and to player input. A tag is # at the end of a line, then a key, a colon and an argument. Tags run before their line shows. Missing media is not an error: the story goes on without it.

Tag Argument What it does Lasts
bg: <id> picture Sets the background Until the next bg
bg: none Clears the background
img: <id> [frame] picture Shows a picture with the line This line
music: <id> sound Starts a looping track Until the next music
music: none Stops the music
music: default Plays the menu theme
sfx: <id> sound Plays a sound once Until it ends
video: <id> video Plays a video (skippable) Until it ends or is skipped
map: <id> picture Shows a Map button Until the next map
map: none Hides the Map button
wait: <n>s Holds back the passage That many seconds
input: <var> [keypad] on a choice Asks the player to type Until ink changes the variable

A tag without : is a note. Unknown tags are ignored.

Backgrounds

bg sets a full-screen background picture. 

The mist clears. # bg: village

bg: none clears it. Without a background (or while it loads), the app shows the tale's theme picture, or if there is none, the app's own art.

Pictures and frames

img shows a picture with the line. An optional frame word sets the border. 

A worn map lies on the table. # img: old-map mat

The six frames:

Frame Look
plain Rounded corners, a shadow, no border.
line A thin line around the picture.
mat A soft mat around the picture (padding, thin line, rounded corners).
double A thin line and a second line outside it. The default when no frame is given.
glow A warm glow around the picture.
print A tilted snapshot on paper, like a photograph.

Pictures are shown at half pixel size (retina). Make them twice as wide as they should appear on screen.

Music

One track at a time, looping. A new music tag crossfades from the current track.

# music: night-theme
The stars come out.
# music: none 5s
  • Without a transition word, the engine uses its own default crossfade.
  • cut switches instantly.
  • A time like 8s or 2.5s sets the crossfade length.
  • music: none fades to silence.
  • music: default goes back to the menu theme.

On a new game, the first passage cuts to its music (no crossfade from the menu).

Sound effects

sfx plays a sound once, from start to end.

# sfx: door-slam
The door falls shut behind you.

Several sounds can play at the same time. The story cannot stop or fade them. All sounds end when the player leaves the tale.

Video

video plays a video over the story. The player can skip it. If the browser blocks autoplay, a Play button shows. 

# video: intro

The story continues when the video ends or is skipped.

Maps

map gives the player a Map button in the top bar. It opens the picture in a zoomable, pannable window. 

=== harbour ===
# map: harbour-map
Gulls wheel over the quay.

map: none hides the button. Make a map at least twice the display size, so the player can zoom in on details.

Pauses

wait holds back the rest of the passage (its remaining text and choices) for a number of seconds. A tag runs before its line shows. 

The door creaks open.
# wait: 2s
Something moves inside.

The player cannot skip a wait.

Text input

input goes on a choice, inside the brackets. The player types text, which goes into an ink variable. 

VAR code = ""
+ [Enter the code #input: code keypad]
    {code == "1984": The lock opens.|Nothing happens.}

A window opens with a text field, Cancel, Clear and Submit. keypad after the variable name shows a tappable keypad picture. The variable must be declared as a VAR in the story.

The tale editor

What you need

A computer with a wide screen. On a phone or narrow tablet, the editor says so and offers to go back to the app. The editor is at the editor page. The app's main menu links to it under "Write a tale".

The editor loads in under 750 KB of code. Media conversion (video encoder, AVIF encoder) loads on demand when you drop files.

Learn by example

The fastest way to learn is to open the worked example. Press New, then pick The worked example ("No Experience Required"). It is a complete tale with five ink files, pictures and music. Read the code, change things, and watch the preview update. The comments in the story explain what each part does. It uses most elements (scenes, choices, speech, variables, backgrounds, pictures, music and sound effects), except video and maps. Each browser tab holds its own tale, so you can keep the example open in one tab while writing your own tale in another.

The layout

The code editor sits on the left. The right side switches between Preview, Story map and Media. The Theme tab replaces the code editor when open.

The header bar

From left to right:

  • Back arrow saves and goes to the app.
  • Title button opens the Tale details dialog.
  • Status ("Saved in this browser") opens the storage report.
  • New starts a new tale (from a template or an empty file).
  • Open opens a .otproject, a .zip, or an .ink file. It does not open .tale files (those are for playing, not editing).
  • Save downloads the tale as a .otproject file (a ZIP of the source).
  • Publish .tale builds a .tale file for players.
  • About describes the editor.
  • Help shows the ink quick reference.

Starting a tale

New offers:

  • An empty tale.
  • A short starter: a gate, a forest and a name to type.
  • Three roads: a story that splits into paths, each with its own end.
  • A hub: a place to come back to, with things to find before the way out.
  • A code door: a choice that asks the player to type, with the keypad.
  • A conversation: answers that change how someone feels, and an end that shows it.
  • The worked example: "No Experience Required", a tale with five files, pictures and music.

The code editor

The editor uses Ace with ink syntax highlighting and folding. Search with Cmd+F (or Ctrl+F on Windows and Linux).

The editor checks the story about 400 ms after you stop typing. Problems show in the left margin and in the problems list below the code. The editor saves the tale to the browser about 800 ms after you stop typing.

File tabs

main.ink is always the first tab. + File adds a new .ink file and its INCLUDE line in main.ink. The close button (x) on a tab removes the file and its INCLUDE. Tabs can be reordered by dragging (except main.ink).

The download button on the active tab saves that single file as .ink text.

Insert toolbar

Two groups of buttons for inserting ink patterns at the cursor:

Scenes and links: Scene (a knot), Go to (a divert to a scene or END).

In a scene: Choice, Join (a gather), Speech (offers existing speaker names), Media (switches to the Media tab).

More (dropdown): stitch, bold italic (actionable text), pictures and sound tags, map, pause, typed input, variables, conditionals, varying text, notes, and a link to Help.

Problems list

Below the code editor: a count of errors, warnings and notes. Click a problem to jump to its file and line.

  • Errors: ink errors, a tag that names a missing or wrong-type asset, a bad tag, input without its VAR. Errors stop Publish.
  • Warnings: unknown tags, unused media. Warnings do not stop Publish.
  • Notes: TODO: lines in the story.
  • Runtime errors from the preview also appear here.

The preview

The right side's default tab. An iframe that runs the real game screen: exactly what the player sees. The title card shows on open. The story starts only when you press a key or tap.

After a code change, the preview replays your choices to return to the passage you were on. It suppresses that passage's sounds, videos and waits during the replay. Play passage again replays with sounds. Restart goes back to the title card with new random numbers. Stop mutes the preview.

The choices counter ("N choices in") shows how deep you are.

Story map

A visual graph of the tale's scenes (knots) and their parts (stitches). Each box shows a scene's choices, with arrows to their targets. Dashed boxes are unreachable scenes.

Click a box or a choice row to jump to that line in the code editor. Zoom with the minus and plus buttons. The map reads the ink text directly, so it works even when the story has compile errors.

Media

Drop files anywhere on the page, or use the "add files" button. The file's name becomes its asset ID: Forest Clearing.avif becomes forest-clearing. The asset can be renamed later with the Rename button.

Each media card shows a preview and buttons for inserting tags:

  • Pictures: Background, Picture, Map, Cover (sets the title card image).
  • Sounds: Music, Sound.
  • Videos: Video.
  • All types: Rename, Credit (records who made the file), Remove.

Rename changes the asset ID. The editor updates every tag in the story that references the old name, and updates the cover and credits if they use it. You can also click the pen icon next to the asset name.

Remove asks first, and shows how many tags in the story use the file. On "Remove", the editor deletes the file and strips every tag that references it from the ink text, including lines that become empty. You do not need to clean up the tags by hand.

Sort by name (A to Z, Z to A) or by type (pictures, sounds, videos).

Media conversion

All conversion runs on your device. Nothing is uploaded. A file already in the right format and within the limits goes in as it is.

Pictures

AcceptedPNG, JPEG, WebP, HEIC, HEIF, GIF, BMP, TIFF
OutputAVIF
Encoderlibavif (via jSquash WebAssembly), quality 60, speed 6
Max long edge2560 px. Larger pictures are scaled down (high-quality resampling).
Size guideline500 KB per picture. Larger files get a warning but are not refused.
Pass-throughAn .avif file goes in unchanged. A .webp file goes in unchanged when the tale already has the same picture as AVIF (then the WebP is the fallback).

Pictures are shown at half pixel size (retina scaling). Make them about twice as wide as they should appear on screen.

Sounds

AcceptedMP3, WAV, FLAC, Ogg, Opus, AAC, AIFF, M4A
OutputM4A (AAC in an MP4 container)
EncoderWebCodecs (the browser's own AAC encoder)
Sample rate48 kHz
Bitrate128 kbps, constant bitrate
ChannelsMono or stereo. Files with more channels are mixed down to stereo.
Max size10 MB per sound (about 10 minutes at 128 kbps). Longer files are refused before conversion starts.
Pass-throughAn .m4a file with AAC, no video track and within 10 MB goes in unchanged.

Videos

AcceptedMP4, MOV, WebM, MKV, M4V
OutputMP4 (H.264 video + AAC audio)
EncoderWebCodecs (the browser's own H.264 and AAC encoders), via Mediabunny
Video bitrate5 Mbps
AudioAAC, 48 kHz, 128 kbps
Max width1920 px. Wider videos are scaled down, keeping the aspect ratio.
Max size200 MB per video (about 5 minutes at 5 Mbps + 128 kbps). Longer files are refused before conversion starts.
Pass-throughAn .mp4 file with H.264 video, AAC or no audio, no wider than 1920 px and within 200 MB goes in unchanged. A MOV with H.264 within the size limit copies the picture track without re-encoding.

If the browser cannot encode a video's codec, it says so and asks you to convert the file to MP4 with H.264 and AAC first (for example with FFmpeg or HandBrake).

Tale size

There is no hard limit on the whole tale's size, but the editor warns when the total passes 1 GB: a big tale takes long to import and fills the player's storage.

Theme

The Theme tab (the last tab in the code editor) gives the tale its own colour palette and a background picture.

  • Own theme toggles whether the tale has its own colours or uses the player's.
  • Start from sets all six colours to Classic, Neon City, or Scandinavian 80s as a starting point. It asks before replacing manually picked colours.
  • The colour wheel picks a colour: hue around the ring, saturation from the centre out, brightness on the slider, or type a hex code.
  • The six colour roles: Background, Text, Muted text, Highlights, Borders, Separators. Each shows a swatch, its hex value and (for text colours) the contrast ratio against the background. A ratio below 4.5:1 is flagged.
  • Match the background resets the five non-background colours to follow the background, after a confirmation if any were picked by hand.
  • Picture chooses one of the tale's pictures as a background image, or "None".

Changes show in the preview immediately.

Tale details

Opened from the title button in the header bar, or before the first Publish.

  • Title (required).
  • Authors (comma-separated).
  • Language (a code: en, nl, sv, and so on).
  • Description (optional).
  • Licence (optional, an SPDX name like CC-BY-4.0).
  • ID (derived from the title if left empty).
  • Version (made by Publish if left empty).

Publishing

Publish .tale builds a tale file for players.

  1. It asks for the tale details the first time.
  2. It refuses while errors exist.
  3. It plays the tale 50 times with random choices, to catch crashes and missing assets.
  4. It packs the .tale file and downloads it.

Import the file in the app to play it, or share it with others.

Projects and tales

Two kinds of file:

  • .otproject: the tale's source, to open in the editor again. Keep this. It is a standard ZIP holding story/ (plain .ink files), media/ (pictures, sounds, videos) and tale.json (title, authors, language, theme, credits). You can unzip it and open the .ink files in Inky or any text editor.
  • .tale: the compiled tale, for playing and sharing. Import it in the app. Also a ZIP, holding the compiled ink JSON (no .ink source) and all media. It cannot run code: the app checks every file against its hash before playing. Each tale has an ID and a version, so the app can detect updates.

Open takes .otproject, .zip of a tale source, or a plain .ink file. It does not take .tale files.

Your source is standard .ink throughout. Every media tag is a standard ink tag that Inky and inklecate silently ignore. No EXTERNAL functions, no custom syntax. Write here, leave any time, take your files with you.

Both format specifications are on the wiki: story package spec and project file spec.

Where the work is kept

The tale is stored in the browser's IndexedDB, at the site's address. The editor saves after each change.

Each browser tab holds its own tale (via Web Locks). After a reload, a tab resumes its tale. Closing or navigating away asks when unsaved work, media tasks, or unkept media would be lost.

Safari may delete site data after 7 days without a visit. Save the .otproject file as a backup.

The "Kept in this browser" report (the status button in the header bar) shows the tale's save status, its size, whether the browser has promised persistent storage, and other tales kept in this browser.

Keyboard shortcuts

Shortcut Action
Cmd+S (Ctrl+S) Save now (the editor auto-saves, so this forces an immediate save).
Cmd+F (Ctrl+F) Search in the code.

Closing or navigating away asks when unsaved work exists.

Browser storage

The app stores autosaves and settings in localStorage, and imported tales in IndexedDB. The editor stores the tale being written in its own IndexedDB. Nothing syncs between devices. Nothing leaves the device.

Safari may delete site data after 7 days without a visit. Other browsers keep it until the user clears it.

"Clear saved data" in Settings deletes the app's data (autosaves, imported tales, settings). It does not delete the editor's data.

Writing a tale in ink

Ink is a plain-text language for interactive stories, made by inkle. Five words name the shapes of a story:

Word Looks like What it does
knot === name === A scene.
stitch = name A part of a scene.
divert -> name Goes to a scene or a stitch.
choice * or + Something the player picks.
gather - Where the branches meet again.

Speech is Name: line. Media is tags (see Media tags above).

The editor's Help button shows a quick reference with examples and an Insert button for each pattern. The More menu inserts patterns too.

What ink can do

  • Variables and functions. VAR courage = 0, conditional text {courage > 2: You stand tall.}.
  • Random numbers and varying text. {~Rain.|Fog.|Sun.} picks one at random. {First time.|Second time.|After that.} cycles.
  • Conditional choices. * {courage > 2} [Climb] shows only when the condition holds.
  • Repeatable choices. + stays; * goes away once picked.
  • Text input. # input: variable opens a text field. The result goes into an ink variable.
  • Multiple files. INCLUDE act2.ink splits a story across files.
  • Tunnels, threads and lists. They work, but most tales do not need them.

The full language is in inkle's manual: Writing with ink.

Accessibility

  • Languages. Tales set their language. Ink handles Unicode, including diacritics and non-Latin alphabets.
  • Screen readers. The app uses semantic HTML and ARIA labels. Not yet tested with screen readers.
  • Timed events. The wait tag pauses text for a set number of seconds and is not skippable. Videos are skippable.
