Features & Comparison App Editor Wiki

New Platform Checklist

Answers to the standard questions for new IF platforms (Hidnook's list). See also the features and comparison page.

Development

Where is the documentation? The wiki covers the app, the editor and every media tag. The editor's Help button has a quick ink reference. The formats have full specifications: story package spec and project file spec.
Extending the system? Stories are standard ink, so anything ink supports works. The media tags are documented in the spec, and the runtime is MIT-licensed. If you write ink in another editor, every media tag is a standard ink tag that Inky silently ignores.
Extensions, modules, libraries? Not currently. Stories use ink's built-in features (variables, functions, tunnels, threads, lists). Media is handled through tags, not extensions.
How easy to pick up? The editor ships with five starter templates and a worked example ("No Experience Required") with comments that explain every feature. The Help button covers the five words you need to start writing. The wiki documents every tag and feature.
Syntax? Standard ink. === scene ===, * [Choice], -> scene, # music: track. See inkle's Writing with ink.

Environment

Website only or separate IDE? Browser editor at the site. No install. You can also write .ink in any text editor and open it in the editor.
Save projects locally? Yes. Save downloads an .otproject (ZIP of the full source: ink files, media, metadata). Open loads it back. Nothing is stored on a server. Project file spec.
Offline editing? Not yet, but once the full source is public you can run your own localhost. There is already a macOS app (not yet public).
WYSIWYG vs code? Code editor with a live preview that shows exactly what the player sees and replays your choices when you edit. No visual/node editor, but the story map gives a graph of all scenes and choices. See features.
Spell check? Your browser's built-in spell check works, or download the .ink files and use any spell checker.

Exporting and publishing

Exportable as playable websites? Publish makes a .tale file that players import in the browser app. Not a standalone HTML page, but the app itself is static files you can host anywhere. Tale format spec.
Download and play outside the platform? The .tale is a standard ZIP (data only, no code). The app is static HTML, CSS and JS with no server, so you can self-host it or run it from a local file. A macOS desktop app also exists (not yet public).
Share freely? Yes. The author owns their .tale. Distribute however you like.
License on games? The app is MIT-licensed. Your tales are yours, under whatever licence you choose and that fits your assets. There is no user agreement that claims rights over your work.
Play without an account? Yes. No account exists. No registration, no login, no tracking. Open the app and play.

Logic and mechanics

Variables, functions? Yes. Ink has global variables, functions, tunnels, threads and lists. Conditionals gate choices and text on any variable or combination of variables.
How complex? As complex as ink allows. Ink powers commercial games like 80 Days and Heaven's Vault. The publish step runs 50 random playthroughs to catch dead ends and errors before you share.
Random number generation? Yes. {~option|option|option}.
Text input? Yes. # input: variable opens a text field. # input: variable keypad adds a tappable keypad.
Repeatable choices? + stays; * goes away once picked.
World model? No built-in world model. Ink variables and conditional logic can simulate one.
Linear storylines? Yes. Ink handles linear, branching and mixed structures. The story map in the editor shows whichever structure you build.

UI and UX

Easy to style? Tales can bring their own colour theme (six colours and a background picture) via the editor's Theme tab. The editor checks contrast for you. No CSS needed. See features.
Alternative colour schemes? Three app themes. Each tale can override them with its own.

Platform comparison

What does it do that others struggle with? Media as a first-class feature: drop in images, audio, video and maps, the editor converts them. A shared player that separates story from runtime, so one app plays any tale. Mobile-friendly output without extra work. A browser editor with live preview and automatic media conversion. One .tale file to share. See the full comparison with other tools.
What does it struggle with? The editor GUI is solid but still growing: no drag-and-drop story building or interactive map editing yet. No standalone HTML export. No multiplayer. New, small community. I focused on robustness and usability over breadth of features.

AI

Was AI involved? Yes. I could not have built it without Claude by Anthropic. The design and creative decisions are mine.
Is AI a part of the features? No. No AI runs in the app or editor. Authors decide their own level of AI use.

Business model

Paid or free? Free. No ads, no tracking, no account, no subscription. You are not the product.
Monetization? The app is free. I may accept donations for stories I write, or take commissions to build tales for museums, courses and the like. The app itself will never be monetized. There is no user agreement that claims any rights over authors' work.
Compared to Itch? Not a marketplace. Authors distribute .tale files however they choose, including on Itch.

Proof of concept

Example game? "No Experience Required" ships with the app. A short dystopian tale using scenes, choices, speech, variables, backgrounds, pictures, music and sound.
Best demonstration? Play it on your phone. Then open it as the worked example in the editor on a computer.

Accessibility

Languages other than English? Yes. Ink handles Unicode, diacritics and non-Latin alphabets. The app and editor interface is in English, but story content works in any language.
Screen-reader friendly? Semantic HTML and ARIA labels throughout. Not yet tested with screen readers, and I would welcome feedback on this.
Timed text? The # wait tag pauses text. Not skippable currently. Videos are skippable.
